# 晓空今天吃什么 · 微信小程序首次上线清单

小程序简称为「今天吃什么」，主体为中国大陆个人。「工具 / 信息查询」是拟选类目，请以公众平台对该主体开放的类目及审核要求为准。

## 1. 配置 AppID 和上传密钥

- [ ] 管理员登录[微信公众平台](https://mp.weixin.qq.com/)，在「开发管理 → 开发设置」核对小程序 AppID。给负责预览和测试的微信账号分配开发或体验权限。
- [ ] 管理员在「小程序代码上传」下载本 AppID 的上传私钥，将执行预览和上传命令的主机公网出口 IP 加入白名单。将私钥放在仓库外，macOS/Linux 可用 `chmod 600` 限制文件权限。[微信官方 miniprogram-ci 文档](https://github.com/wechat-miniprogram/miniprogram-ci-dist)
- [ ] 在仓库根目录执行 `cp .env.example .env.local`（已有文件则直接编辑），或将以下变量注入本机执行环境。保留 `.env.local` 的 Git 忽略规则。

| 变量 | 取值 |
| --- | --- |
| `TARO_APP_ID` | 上述小程序的真实 AppID |
| `WEAPP_PRIVATE_KEY_PATH` | 仓库外上传私钥的绝对路径 |
| `WEAPP_VERSION` | 上传所用的版本号，例如 `0.1.0` |
| `WEAPP_DESC` | 可选的版本说明 |

## 2. 构建、导入和预览

在仓库根目录使用 Bun 和 Node.js。先完成离线检查。

```bash
bun ci
bun run typecheck
bun run test
bun run build:weapp
bun run smoke:weapp
```

- [ ] 检查 `dist-weapp/project.config.json` 中的 `appid` 与本次配置一致，`miniprogramRoot` 为 `./`。构建检查可在未配置 AppID 时运行。
- [ ] 登录[微信开发者工具](https://developers.weixin.qq.com/miniprogram/dev/devtools/download.html)，选择「导入项目」，目录选本仓库的 `dist-weapp/`，AppID 核对为目标小程序。持续调试可从仓库根目录运行 `bun run dev:weapp`。
- [ ] 在开发者工具中点击「预览」，或在已加入白名单的主机上执行下列命令。获授权的测试成员用手机微信扫 `artifacts/weapp/preview.jpg`。

```bash
bun ci --cwd tools/weapp
bun run preview:weapp
```

预览和上传脚本每次都会进行生产构建，并检查新生成的项目配置。请在同一工作区逐次执行发布命令，并在执行时停止 `dev:weapp` 的监听构建。

## 3. iOS 和 Android 真机验收

两台真机都执行以下步骤，记录机型、系统、微信版本及结果。模拟微信 API 的冒烟测试覆盖生成的页面逻辑，下面各项需要在手机微信里验证。

- [ ] **首屏与安全区**。使用窄屏机型和带底部手势区的机型，打开首页时转盘和「开始随机选择」均完整可见。页面能顺滑滚到清单底部，系统手势区域不会遮住按钮。
- [ ] **抽选与弹窗**。保留一个启用项时多次抽选，只出现该项。再启用多个选项，检查停转后弹窗显示实际选中的菜品、店铺、区域和备注，「好，就吃这个」可关闭，「再抽一次」可重新抽取。开启「跳过旋转动画」后也能正常出结果。
- [ ] **触摸与键盘**。测试快速连续点击、点击清单条目编辑时的滚动定位、弹窗及长文字的滚动，以及键盘弹起和收回时所有输入框和保存按钮的可达性。确认键盘收起后页面仍可滚动。
- [ ] **清单与存储**。新增、编辑、暂停、重新启用和删除后退出再进，核对内容。停用全部时主按钮禁用，删空后再进仍为空。测试恢复推荐清单的取消和确认。
- [ ] **分享与离线使用**。打开自定义菜单或带私人备注的结果弹窗，通过右上角「转发给朋友」给有权限的体验成员。核对卡片使用固定转盘封面，对方可打开首页且看不到你的本地菜单或备注。小程序加载完成后断网，确认仍可抽选和编辑菜单，无需登录、云数据库或服务器。

## 4. 上传开发版并设置体验版

在同一固定出口主机上完成配置后运行。

```bash
bun run upload:weapp
```

- [ ] 在「版本管理」的开发版本列表，核对刚上传的版本号和说明。把该开发版设为体验版，配置体验成员权限，邀请成员扫体验版二维码，并在体验版上复测。
- [ ] 当前使用固定出口主机执行本地命令。公开仓库没有固定出口的自托管 Runner，GitHub Actions 继续做构建与测试。若今后有独立、受控的发布 Runner，再启用仅手动触发的上传工作流。届时用受保护环境的 GitHub Secrets 注入 AppID 和上传私钥，私钥写入权限受限的临时文件并在作业结束时清理，作业仅运行开发版上传。[GitHub 自托管 Runner 指南](https://docs.github.com/en/actions/how-tos/manage-runners/self-hosted-runners/add-runners)

## 5. 备案、提审和发布

- [ ] 管理员在公众平台发起小程序备案，按后台提示提交个人主体资料并跟进。首次上架前应确认备案完成。[工信部备案通知](https://nmca.miit.gov.cn/zwgk/zcwj/wjfb/art/2023/art_1e97112f056141ffba534dfe9e822063.html)
- [ ] 核对名称、简称、头像、简介、实际提供的服务和适用类目。确认审核人员可直接进入首页完成抽选和管理清单，并提交平台要求的材料。
- [ ] 核对「用户隐私保护指引」及后台声明与实际行为一致。清单和自行填写的备注只保存在本机，应用无需账号，也没有定位、广告、统计、云数据库和远程餐厅查询。分享卡片使用固定封面、首页入口和标题。
- [ ] 真机验收通过后，由有权限的成员在「版本管理」选中核对过的版本，按平台要求填写审核说明并提交审核。
- [ ] 审核通过后，由有权限的成员核对获批版本并手动发布。用普通微信账号打开正式版，复查首页、抽取和分享。
